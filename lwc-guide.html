01What is LWC

Lightning Web Components (LWC) is Salesforce's modern component framework based on web standards — custom HTML elements, ES6+ JavaScript, and CSS. It replaced Aura Components as the recommended approach from Spring 19 onwards. LWC is faster, more standards-compliant, and easier to test than Aura.

FeatureLWCAura
StandardWeb Components standardProprietary Salesforce framework
PerformanceFaster — native browser renderingSlower — framework overhead
JavaScriptES6+ modulesAura-specific syntax
TestingJest — standard JS testingLimited testing options
InteropCan use Aura components inside LWCCan use LWC inside Aura
StatusActive — new features added every releaseMaintenance mode only

import { LightningElement, api, track, wire } from 'lwc';

03Lifecycle Hooks

LWC components go through a defined lifecycle from construction to removal. Understanding when each hook fires is critical for data fetching, DOM manipulation, and cleanup.

HookWhen It FiresUse ForCan Access DOM?
constructor()Component instance createdInitialising class variables only❌ No
connectedCallback()Component inserted into DOMSubscribing to events, initial data fetch via imperative Apex✅ Yes
renderedCallback()Every render completesDOM manipulation after render, pre-filling inputs, third-party library init✅ Yes
disconnectedCallback()Component removed from DOMUnsubscribing from events, cleanup❌ No
errorCallback(error, stack)Child component throws errorError boundary handling❌ No
Common Mistake — renderedCallback Infinite Loop

renderedCallback fires on every render. If you update a property inside it, that triggers another render, which fires renderedCallback again — infinite loop. Always use a boolean flag to run DOM manipulation only once.

JavaScriptrenderedCallback pattern — textarea pre-fill
export default class MyForm extends LightningElement {
    @api initialValue;
    _rendered = false; // Guard flag

    renderedCallback() {
        if (this._rendered) return; // Only run once
        this._rendered = true;

        // Access native textarea after DOM is ready
        const textarea = this.template.querySelector('textarea');
        if (textarea && this.initialValue) {
            textarea.value = this.initialValue;
        }
    }
}

04Reactive Properties

DecoratorPurposeWhen to Use
@apiPublic property — parent can read/writeComponent inputs, expose to parent, expose to App Builder
@trackDeep reactivity for objects and arraysWhen you mutate a property inside an object or array and need the template to re-render. Primitives do NOT need @track.
(none)Primitive reactive propertyStrings, numbers, booleans — reactive by default since Spring 20. No @track needed.
@wireReactive wire service connectionReading Salesforce data that should refresh when its parameters change
Primitives are reactive without @track

Since Spring 20, all primitive properties (String, Number, Boolean) are reactive without @track. You only need @track when you mutate a property inside an object — e.g. this.myObj.name = 'x' — and need the template to re-render. Assigning a new object reference (this.myObj = newObj) is always reactive without @track.

//Native Select Reactive Binding Fix

Native HTML <select> elements do not react to value changes the same way lightning-combobox does. This is a real bug pattern encountered in the FAPO project.

JavaScriptThe isSelected getter pattern
// PROBLEM: Native <select> does not reflect value changes reactively
// <option value={opt.value}> does NOT highlight the selected option

// SOLUTION: Use an isSelected getter in your option objects
get fundingOptions() {
    return [
        { label: 'Federal', value: 'federal', 
          isSelected: this.selectedFunding === 'federal' },
        { label: 'State', value: 'state',   
          isSelected: this.selectedFunding === 'state' },
    ];
}

// In HTML: <option value={opt.value} selected={opt.isSelected}>
// Now when selectedFunding changes, getter re-evaluates,
// and the correct option is highlighted

05Wire Adapters

Wire adapters connect your component to Salesforce data reactively. When the parameters change, the wire service re-fetches automatically.

JavaScriptWire examples
import { LightningElement, api, wire } from 'lwc';
import { getRecord, getFieldValue } from 'lightning/uiRecordApi';
import { getPicklistValues, getObjectInfo } from 'lightning/uiObjectInfoApi';
import LOAN_STATUS from '@salesforce/schema/Loan_Application__c.Status__c';
import getLoanDetails from '@salesforce/apex/LoanController.getDetails';

export default class LoanCard extends LightningElement {
    @api recordId;

    // Wire getRecord — auto-refreshes when recordId changes
    @wire(getRecord, { recordId: '$recordId', fields: [LOAN_STATUS] })
    loan;

    // Computed getter from wire result
    get status() {
        return getFieldValue(this.loan.data, LOAN_STATUS);
    }

    // Wire an Apex method — reactive when recordId changes
    @wire(getLoanDetails, { loanId: '$recordId' })
    wiredLoan({ error, data }) {
        if (data) {
            this.loanData = data;
        } else if (error) {
            console.error(error);
        }
    }
}

//Wire vs Imperative Apex — When to Use Which

ScenarioUse WireUse Imperative
Reading data on load✅ Yes — auto-fetchesCan use either
Data depends on a changing property✅ Yes — re-fetches automatically❌ Must call manually
DML — insert/update/delete❌ Wire is read-only✅ Must use imperative
Call on button click❌ Not triggered by events✅ Imperative in handler
Show loading spinnerComplex — need to check wire state✅ Easier — set isLoading flag
Error handlingVia error property✅ Try/catch in async function

06Calling Apex from LWC

JavaScriptImperative Apex with async/await
import { LightningElement, track } from 'lwc';
import { ShowToastEvent } from 'lightning/platformShowToastEvent';
import getLoanStatus from '@salesforce/apex/LoanController.getLoanStatus';

export default class StatusChecker extends LightningElement {
    @track loanData;
    isLoading = false;
    error;

    async handleCheckStatus() {
        this.isLoading = true;
        this.error = undefined;
        try {
            this.loanData = await getLoanStatus({
                loanNumber: this.loanNumber,
                contactId: this.contactId
            });
            this.dispatchEvent(new ShowToastEvent({
                title: 'Success', message: 'Status retrieved',
                variant: 'success'
            }));
        } catch (error) {
            this.error = error?.body?.message || 'An error occurred';
        } finally {
            this.isLoading = false;
        }
    }
}

08File Uploads — ContentVersion Pattern

Uploading files in LWC for Experience Cloud requires converting to base64 and creating ContentVersion records via Apex. The standard lightning-file-upload component does not work reliably for community portal users.

HTMLFile input in template
<template>
    <input type="file" accept=".pdf,.jpg,.png,.doc,.docx"
           onchange={handleFileChange} />
    template lwc:if={isUploading}>
        <lightning-spinner></lightning-spinner>
    </template>
</template>
JavaScriptFileReader → base64 → Apex → ContentVersion
handleFileChange(event) {
    const file = event.target.files[0];
    if (!file) return;
    const reader = new FileReader();
    reader.onload = async () => {
        const base64 = reader.result.split(',')[1]; // strip data URI prefix
        this.isUploading = true;
        try {
            const result = await uploadDocument({
                base64Data: base64,
                fileName: file.name,
                contentType: file.type,
                recordId: this.recordId
            });
            this.dispatchEvent(new CustomEvent('uploaded', { detail: result }));
        } catch(e) {
            console.error('Upload failed', e);
        } finally {
            this.isUploading = false;
        }
    };
    reader.readAsDataURL(file);
}
ApexUpload controller — ContentVersion + ContentDocumentLink
@AuraEnabled
public static String uploadDocument(
        String base64Data, String fileName,
        String contentType, String recordId) {

    ContentVersion cv = new ContentVersion();
    cv.Title           = fileName;
    cv.PathOnClient    = fileName;
    cv.VersionData     = EncodingUtil.base64Decode(base64Data);
    cv.FirstPublishLocationId = recordId;
    insert cv;

    // Get ContentDocumentId for the link
    ContentVersion inserted = [
        SELECT ContentDocumentId FROM ContentVersion
        WHERE Id = :cv.Id WITH SYSTEM_MODE LIMIT 1
    ];

    return inserted.ContentDocumentId;
}

//Viewing Uploaded Files — PDF and Office

Common Bug — File Preview URLs

Rendition URLs from ContentVersion do not work for PDF and Office files in Experience Cloud. Use the servlet download URL instead: /sfc/servlet.shepherd/version/download/{versionId}. This works for all file types including PDF, Word, and Excel.

09Common LWC Patterns

//Show/Hide Loading Spinner Pattern

JavaScript
// Always use try/catch/finally so spinner never gets stuck ON
async loadData() {
    this.isLoading = true;
    try {
        this.data = await getMyData({ id: this.recordId });
    } catch (e) {
        this.error = e?.body?.message;
    } finally {
        this.isLoading = false; // always runs — spinner always stops
    }
}

//Refresh on Save Pattern

JavaScriptUsing refreshApex after DML
import { refreshApex } from '@salesforce/apex';

// Store wire result reference
@wire(getLoanData, { loanId: '$recordId' })
wiredLoan; // store the entire wire result

async handleSave() {
    await saveLoanData({ data: this.updatedData });
    // Refresh the wired data after save
    await refreshApex(this.wiredLoan);
}

10LWC in Experience Cloud

IssueRoot CauseFix
ContentDocumentLink query returns empty for portal usersFile access respects running user's FLS regardless of without sharing keywordQuery ContentVersion separately or use WITH SYSTEM_MODE on SOQL
CRUD operations fail for community usersCommunity users have restricted profiles — DML blockedUse AccessLevel.SYSTEM_MODE on Database.insert() / Database.update() calls
@wire getRecord returns null in communityGuest user profile lacks field-level read accessGrant field-level read on each field via Guest User Profile
lightning-file-upload does not workComponent not supported for guest users in Experience CloudUse native HTML input type=file with FileReader and Apex ContentVersion upload
Custom CSS not applyingLWC CSS is scoped — does not pierce child component shadow DOMUse :host or CSS custom properties for theming. Never use !important to override child styles.

12Best Practices

PracticeWhy
Never put logic in renderedCallback without a guard flagCauses infinite re-render loop
Always use try/catch/finally around Apex callsEnsures loading spinner always clears even on error
Use @salesforce/schema imports for field referencesGets compile-time validation and deployment warnings if field is deleted
Prefer wire for reads, imperative for writesWire is reactive — imperative is flexible. Using each for its purpose keeps code clean.
Use CustomEvent with bubbles:true for child-to-parent across multiple levelsWithout bubbles:true, the event stops at the immediate parent
Never use document.querySelector — always use this.template.querySelectorLWC's shadow DOM means document.querySelector cannot see inside the component's shadow root
Use Lightning Message Service for cross-tree communicationCustomEvents cannot cross the component tree — LMS works across any components on the same page
Name files and folders in camelCase onlyLWC folder and file names must match exactly — PascalCase or kebab-case will fail deployment
