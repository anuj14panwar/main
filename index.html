Financial Aid Payment Office (FAPO)
Team Lead / Technical Lead
Baker Ripley · Nonprofit Financial Aid · iLink Digital Systems · Ongoing

End-to-end Salesforce implementation for Baker Ripley's nonprofit financial aid operations, managing disbursement of financial assistance to thousands of families. The platform handles TFA (Texas Financial Assistance) Pledge Batch approvals, integrates with MIP — an enterprise financial system storing Chart of Accounts, GL entries, Invoices, and Payments — and manages the full document submission and approval lifecycle.

The two biggest technical challenges on this project were the API integration with MIP and the complex multi-stage approval workflows for Pledge Batches. Both required custom architecture decisions rather than standard Salesforce tooling.

  • Integrated Salesforce with MIP financial system using REST and Composite APIs, enabling real-time secure data exchange of Chart of Accounts, GL entries, invoices, and payment records — eliminating manual data entry between systems
  • Architected complex TFA Pledge Batch multi-stage approval workflows with custom rejection routing, Send Back to Case Manager flows, Final Approval handling, and resubmit logic requiring red flag resolution before resubmission
  • Built role-gated LWC modal components where unit/amount/Funding Program editing is restricted by the user's queue role — using custom permission checks within LWC controllers
  • Integrated Adobe Sign for digital agreement workflows within the financial aid approval chain, replacing paper-based sign-off processes
  • Resolved critical Experience Cloud file visibility bug — ContentDocumentLink queries returning empty for portal users even with without sharing — root cause was FLS enforcement regardless of sharing keyword; fixed using WITH SYSTEM_MODE SOQL
  • Implemented red flag display system with filter chips, requiring case managers to resolve all flagged items before a batch can be resubmitted for approval
  • Built Queueable Apex for async custom notifications (Messaging.CustomNotification) to approval stakeholders at each stage transition
  • Architected trigger handler pattern where all approval submission logic lives in the trigger handler and all workitem approval/rejection logic lives in the controller — strict separation of concerns for maintainability
  • Enhanced security using custom Permission Sets and group-based access controls for community users, ensuring CRUD bypass using AccessLevel.SYSTEM_MODE for portal user DML operations

Loan Support Agentforce Agent
Architect / Developer

Autonomous AI agent built using the new Agentforce Studio interface (Agent Script, Subagents, Variables) for NBFC loan customer support. Deployed on Experience Cloud and WhatsApp. Handles loan status queries, document checklist checks, EMI calculations, and human escalations without any scripted decision trees — the Atlas Reasoning Engine routes and responds autonomously.

AI Developer Toolkit — Salesforce + Claude API
Senior Developer
iLink Digital Systems · Internal Tooling · Production

Suite of three AI-powered developer tools built inside Salesforce using Named Credentials to call the Claude API via Apex. Built as LWC components deployable to any org, they give developers AI assistance without leaving Salesforce.

  • Apex Test Class Generator — developer uploads an Apex class, the LWC sends it to Claude API via Named Credential callout, receives a complete test class with positive and negative test methods, and deploys it via Tooling API in one click
  • SetupAuditTrail Analyzer — queries SetupAuditTrail using dynamic SOQL with date/user/action filters, sends results to Claude API for AI summarization, returns a plain English summary of what changed in the org and who made the changes
  • Apex Code Quality Analyzer — file upload LWC accepts an Apex class, sends it to Claude for analysis, returns severity-rated issues (Critical, High, Medium, Low) with specific line references and a quality score out of 100
  • All three tools use the same Named Credential pattern (callout:Anthropic_API) ensuring consistent auth handling and no hardcoded API keys anywhere in the codebase

Paycor Tech Debt Migration
Senior Salesforce Developer

Large-scale technical debt remediation project migrating legacy automation to modern Salesforce patterns. Paycor's org had accumulated significant automation debt — 40+ Process Builders and 30+ Workflow Rules that were slow, untestable, and hitting governor limits. The project replaced all of them with scalable Flows and a custom Apex Trigger Framework.

  • Migrated 40+ Process Builders and 30+ Workflow Rules to Record-Triggered Flows and Apex Triggers — improving execution performance, eliminating duplicate automation conflicts, and making logic unit-testable
  • Implemented a robust Apex Trigger Framework enforcing single-trigger-per-object compliance across all custom objects — handler classes, interface contracts, and bypass mechanisms for admin override
  • Refactored and optimized Apex code in alignment with Salesforce best practices — eliminated redundancies, reduced SOQL calls inside loops, consolidated DML operations, and improved bulkification throughout
  • Established code review standards and trigger framework documentation that the client's internal team adopted as the org-wide standard going forward
