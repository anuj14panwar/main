01Apex Basics

02Governor Limits — The Most Important Concept

Salesforce is a multi-tenant platform. Governor limits prevent any single org from consuming too many shared resources. Exceeding a limit throws a LimitException that cannot be caught.

LimitSynchronousAsynchronousMost Common Violation
SOQL queries100200SOQL inside a for loop
SOQL rows returned50,00050,000Querying without LIMIT
DML statements150150DML inside a for loop
DML rows10,00010,000Inserting individual records in loop
CPU time10,000ms60,000msHeavy computation in loops
Heap size6MB12MBBuilding huge collections in memory
Callouts100100Callout inside a loop
Future calls50 per transaction—Calling future from loop
Never do SOQL or DML inside a for loop

This is the single most common governor limit violation. Always collect IDs in the loop, then query or DML outside it. Salesforce processes records in batches of 200 — a trigger with SOQL inside a loop will hit the 100 query limit immediately when 1 record is processed per query.

ApexBulkification — correct pattern
// WRONG — SOQL inside loop = governor limit violation
for (Loan_Application__c loan : trigger.new) {
    Contact c = [SELECT Id FROM Contact WHERE Id = :loan.Applicant__c]; // ❌
}

// CORRECT — collect IDs first, query once outside loop
Set<Id> contactIds = new Set<Id>();
for (Loan_Application__c loan : trigger.new) {
    if (loan.Applicant__c != null) contactIds.add(loan.Applicant__c);
}
Map<Id, Contact> contactMap = new Map<Id, Contact>([
    SELECT Id, FirstName, Email FROM Contact WHERE Id IN :contactIds
]); // ✅ One query for all records

List<Loan_Application__c> toUpdate = new List<Loan_Application__c>();
for (Loan_Application__c loan : trigger.new) {
    Contact c = contactMap.get(loan.Applicant__c);
    if (c != null) {
        toUpdate.add(new Loan_Application__c(
            Id = loan.Id,
            Contact_Email__c = c.Email
        ));
    }
}
if (!toUpdate.isEmpty()) update toUpdate; // ✅ One DML for all records

04Synchronous Apex

Synchronous Apex runs in the same thread as the triggering action — a user click, a trigger, a REST callout. It must complete within the CPU time limit (10 seconds) and the transaction's governor limits.

TypeTriggered ByUse For
Apex TriggerDML operations on recordsBefore/after insert/update/delete/undelete logic
@AuraEnabled methodLWC / Aura component callReading and writing data from UI components
REST Apex (WebService)External HTTP callout to SalesforceExposing Salesforce data to external systems
@InvocableMethodFlow, Agentforce Agent, Process BuilderGiving declarative tools access to Apex logic

05Asynchronous Apex — Overview

Asynchronous Apex runs in a separate thread, outside the original transaction. It has higher governor limits and can do things synchronous Apex cannot — like making HTTP callouts from triggers.

06Batch Apex

Batch Apex processes large data sets by breaking them into configurable chunks (scope). Each chunk runs in its own transaction with fresh governor limits. Used in the FAPO project for daily vendor digest and the Paycor migration for bulk data processing.

ApexComplete Batch pattern
public class LoanStatusDailyBatch
        implements Database.Batchable<SObject>, Database.Stateful {

    // Database.Stateful preserves instance variables between chunks
    private Integer processedCount = 0;
    private List<String> errors = new List<String>();

    // start() — returns the query scope. Runs ONCE.
    public Database.QueryLocator start(Database.BatchableContext bc) {
        return Database.getQueryLocator([
            SELECT Id, Status__c, Applicant__c, Contact_Email__c
            FROM   Loan_Application__c
            WHERE  Status__c = 'Under Review'
            AND    Applied_Date__c = LAST_N_DAYS:30
        ]);
    }

    // execute() — runs for each chunk. Batch size default 200, max 2000.
    public void execute(Database.BatchableContext bc,
                         List<Loan_Application__c> scope) {
        List<Loan_Application__c> toUpdate = new List<Loan_Application__c>();
        for (Loan_Application__c loan : scope) {
            // process each record
            loan.Last_Reviewed_Date__c = Date.today();
            toUpdate.add(loan);
            processedCount++;
        }
        Database.update(toUpdate, false); // false = allow partial success
    }

    // finish() — runs ONCE after all chunks. Send summary email, chain another batch.
    public void finish(Database.BatchableContext bc) {
        System.debug('Processed: ' + processedCount + ' loans');
        // Chain another batch if needed:
        // Database.executeBatch(new AnotherBatch(), 200);
    }
}

// Execute: Database.executeBatch(new LoanStatusDailyBatch(), 200);
// The 200 is the chunk size — lower = more transactions, higher = more governor usage per chunk
Database.StatefulWithout itWith it
Instance variablesReset to null between chunksPreserved across all chunks
Use forStateless processingCounters, error lists, aggregations across chunks
PerformanceFaster — no state serializationSlightly slower — state serialized between chunks

07Queueable Apex

Queueable is the modern replacement for @future methods. It supports chaining, type-safe parameters, and monitoring. Used in FAPO for async custom notifications after approval events.

ApexQueueable with chaining
public class SendApprovalNotificationJob implements Queueable {
    private List<Id> loanIds;
    private String notificationType;

    public SendApprovalNotificationJob(List<Id> ids, String type) {
        this.loanIds       = ids;
        this.notificationType = type;
    }

    public void execute(QueueableContext qc) {
        // Send custom notifications
        CustomNotificationType cnt = [
            SELECT Id FROM CustomNotificationType
            WHERE  DeveloperName = :notificationType LIMIT 1
        ];
        Messaging.CustomNotification notif =
            new Messaging.CustomNotification();
        notif.setNotificationTypeId(cnt.Id);
        notif.setTitle('Loan Application Update');
        notif.setBody('Your application has been updated');
        notif.send(new Set<String>{ /* recipient user IDs */ });

        // Chain another Queueable if needed
        if (!Test.isRunningTest()) {
            System.enqueueJob(new UpdateLoanStageJob(loanIds));
        }
    }
}

// Enqueue from trigger:
System.enqueueJob(new SendApprovalNotificationJob(ids, 'Loan_Update'));

10Trigger Framework

A trigger framework enforces single-trigger-per-object compliance and separates the trigger file from the business logic. This is the pattern used in the Paycor migration where 40+ legacy automations were consolidated.

ApexThe trigger — thin, delegates to handler
trigger LoanApplicationTrigger on Loan_Application__c (
    before insert, before update, before delete,
    after insert,  after update,  after delete, after undelete
) {
    // One line. All logic in the handler class.
    new LoanApplicationTriggerHandler().run();
}
ApexTriggerHandler base class
public abstract class TriggerHandler {

    public void run() {
        if (!isTriggerEnabled()) return; // bypass switch
        switch on Trigger.operationType {
            when BEFORE_INSERT  { this.beforeInsert();  }
            when BEFORE_UPDATE  { this.beforeUpdate();  }
            when AFTER_INSERT   { this.afterInsert();   }
            when AFTER_UPDATE   { this.afterUpdate();   }
            when BEFORE_DELETE  { this.beforeDelete();  }
            when AFTER_DELETE   { this.afterDelete();   }
            when AFTER_UNDELETE { this.afterUndelete(); }
        }
    }

    // Subclasses override only what they need
    protected virtual void beforeInsert()  {}
    protected virtual void beforeUpdate()  {}
    protected virtual void afterInsert()   {}
    protected virtual void afterUpdate()   {}
    protected virtual void beforeDelete()  {}
    protected virtual void afterDelete()   {}
    protected virtual void afterUndelete() {}

    private Boolean isTriggerEnabled() {
        // Check custom metadata or custom setting to bypass trigger
        return !Trigger_Bypass__c.getInstance()?.Bypass_Loan_Trigger__c;
    }
}
ApexConcrete handler — only overrides needed contexts
public class LoanApplicationTriggerHandler extends TriggerHandler {

    private List<Loan_Application__c> newList;
    private Map<Id, Loan_Application__c> oldMap;

    public LoanApplicationTriggerHandler() {
        this.newList = (List<Loan_Application__c>) Trigger.new;
        this.oldMap  = (Map<Id, Loan_Application__c>) Trigger.oldMap;
    }

    protected override void beforeInsert() {
        LoanApplicationService.setExpectedDecisionDate(newList);
    }

    protected override void afterUpdate() {
        List<Loan_Application__c> statusChanged = new List<Loan_Application__c>();
        for (Loan_Application__c loan : newList) {
            if (loan.Status__c != oldMap.get(loan.Id).Status__c) {
                statusChanged.add(loan);
            }
        }
        if (!statusChanged.isEmpty()) {
            System.enqueueJob(new SendApprovalNotificationJob(
                new Map<Id, SObject>(statusChanged).keySet(),
                'Loan_Status_Change'
            ));
        }
    }
}

11@InvocableMethod for Agentforce & Flows

@InvocableMethod exposes Apex logic to Flows, Process Builders, and Agentforce agents. The description parameter is critical for Agentforce — Atlas reads it to decide when to call the action.

Apex@InvocableMethod — full pattern
public class MyInvocableAction {
    // Inner class for inputs — must be public
    public class ActionInput {
        @InvocableVariable(
            label='Customer Email'
            description='Email provided by the customer'
            required=true
        )
        public String customerEmail;
    }
    // Inner class for outputs — must be public
    public class ActionOutput {
        @InvocableVariable(label='Result')
        public String result;
    }
    // The method — must be static, must accept List, must return List
    @InvocableMethod(
        label='My Action Label'
        description='Write this in plain English describing WHEN to call it.'
        category='My Category'
    )
    public static List<ActionOutput> execute(List<ActionInput> inputs) {
        return new List<ActionOutput>();
    }
}

12Platform Events

Platform Events are Salesforce's event bus — fire-and-forget messaging between systems. They decouple the publisher from the subscriber and work across orgs and external systems.

ApexPublishing a Platform Event
// Define the event in Setup: Loan_Status_Event__e
// Fields: Loan_Number__c (Text), Status__c (Text), Timestamp__c (DateTime)

public class LoanEventPublisher {
    public static void publishStatusChange(String loanNumber, String status) {
        Loan_Status_Event__e evt = new Loan_Status_Event__e(
            Loan_Number__c = loanNumber,
            Status__c      = status,
            Timestamp__c   = DateTime.now()
        );
        Database.SaveResult result = EventBus.publish(evt);
    }
}

// Subscribe via Apex Trigger on the event object
trigger LoanStatusEventTrigger on Loan_Status_Event__e (after insert) {
    for (Loan_Status_Event__e evt : Trigger.new) {
        // Process the event — create notification, update related records, etc.
    }
}

13Testing Best Practices

PracticeWhy
Use @TestSetup for shared dataRuns once before all test methods in the class — faster than inserting data in every test method
Always test bulk scenarios (200 records)Triggers run in batches of 200 — your code must handle 200 records without hitting limits
Test positive, negative, and edge casesPositive: valid input. Negative: invalid input returns graceful error. Edge: empty lists, null values, boundary values
Use Test.startTest() and Test.stopTest()Resets governor limits within the test — async operations (Batch, Queueable, Future) run synchronously between startTest and stopTest
Never use SeeAllData=trueMakes tests org-dependent and fragile. Always create your own test data.
Assert specific values not just that something ranSystem.assertEquals('Expected', actual) not just System.assertNotEquals(null, result)
Use Test.isRunningTest() to skip Queueable chaining in testsChained Queueables throw errors in test context — always guard with if(!Test.isRunningTest())
ApexTest class template
@IsTest
public class LoanApplicationTriggerTest {

    @TestSetup
    static void setup() {
        Contact c = new Contact(FirstName='Test', LastName='User',
                                   Email='test@test.com');
        insert c;
        List<Loan_Application__c> loans = new List<Loan_Application__c>();
        for (Integer i = 0; i < 200; i++) {
            loans.add(new Loan_Application__c(
                Application_Number__c = 'HL-TEST-' + i,
                Status__c = 'Draft', Applicant__c = c.Id,
                Applied_Amount__c = 1000000, Tenure_Months__c = 120,
                Applied_Date__c = Date.today()
            ));
        }
        insert loans; // Bulk insert 200 records — tests the trigger at scale
    }

    @IsTest
    static void testBeforeInsertSetsExpectedDate() {
        List<Loan_Application__c> loans = [
            SELECT Id, Expected_Decision_Date__c, Applied_Date__c
            FROM   Loan_Application__c LIMIT 200
        ];
        Test.startTest();
        // Trigger runs inside startTest/stopTest for limit reset
        Test.stopTest();
        for (Loan_Application__c l : loans) {
            System.assertNotEquals(null, l.Expected_Decision_Date__c,
                'Expected decision date should be set');
        }
    }
}

RuleWhy it matters
One trigger per object, all logic in handler classesMultiple triggers on same object fire in unpredictable order

Always handle null before string operationsNullPointerException is the most common runtime error in Apex
Use WITH SYSTEM_MODE in agent action SOQLEinstein Agent User has no FLS — queries silently return zero rows without it
