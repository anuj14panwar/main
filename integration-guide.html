01Integration Types Overview

Salesforce integrations fall into two directions — Salesforce calling out to external systems, and external systems calling into Salesforce. Both have multiple approaches depending on data volume, latency requirements, and auth needs.

TypeDirectionProtocolBest For
REST CalloutSalesforce → ExternalHTTP/JSONReal-time single record operations, Claude API, modern APIs
SOAP CalloutSalesforce → ExternalHTTP/XMLLegacy enterprise systems — SAP, Oracle, older financial systems
Composite APISalesforce → SalesforceHTTP/JSONCreating multiple related records in one HTTP request
Bulk APISalesforce ↔ ExternalHTTP/CSV or JSONLoading or extracting millions of records
Platform EventsAny → AnyStreaming/CometDReal-time event-driven integration, decoupled systems
Outbound MessagingSalesforce → ExternalSOAPWorkflow-triggered notifications to external systems
External ServicesSalesforce → ExternalOpenAPI/SwaggerNo-code REST integration via Flow
Change Data CaptureSalesforce → ExternalStreamingNear-real-time record change notifications to external consumers

02REST API Callouts from Apex

The most common integration pattern — calling an external REST API from Apex. Used in the FAPO project to sync with MIP and in the AI Developer Toolkit to call the Claude API.

ApexFull REST callout pattern
public class MIPIntegrationService {

    public static MIPResponse getLoanAccount(String accountCode) {
        Http http = new Http();
        HttpRequest req = new HttpRequest();

        // Named Credential handles auth — no hardcoded credentials
        req.setEndpoint('callout:MIP_API/accounts/' + accountCode);
        req.setMethod('GET');
        req.setHeader('Content-Type', 'application/json');
        req.setHeader('Accept', 'application/json');
        req.setTimeout(30000); // 30 seconds max timeout

        HttpResponse res;
        try {
            res = http.send(req);
        } catch (System.CalloutException e) {
            throw new AuraHandledException('Callout failed: ' + e.getMessage());
        }

        if (res.getStatusCode() == 200) {
            // Deserialise JSON response to typed class
            return (MIPResponse) JSON.deserialize(
                res.getBody(), MIPResponse.class
            );
        } else {
            throw new AuraHandledException(
                'MIP API error: ' + res.getStatusCode() + ' ' + res.getBody()
            );
        }
    }

    public static String createInvoice(MIPInvoiceRequest payload) {
        Http http = new Http();
        HttpRequest req = new HttpRequest();
        req.setEndpoint('callout:MIP_API/invoices');
        req.setMethod('POST');
        req.setHeader('Content-Type', 'application/json');
        req.setBody(JSON.serialize(payload)); // serialize Apex object to JSON
        req.setTimeout(30000);

        HttpResponse res = http.send(req);
        if (res.getStatusCode() != 201) {
            throw new AuraHandledException('Failed to create invoice');
        }
        Map<String, Object> responseMap =
            (Map<String, Object>) JSON.deserializeUntyped(res.getBody());
        return (String) responseMap.get('invoiceId');
    }

    // Typed response class — maps JSON fields to Apex properties
    public class MIPResponse {
        public String  accountCode;
        public String  accountName;
        public Decimal balance;
        public String  status;
    }
}
Callouts cannot be made after DML in the same transaction

If you insert/update a record and then try to make an HTTP callout in the same synchronous transaction, Salesforce throws: "You have uncommitted work pending". Solutions: use @future(callout=true), Queueable implementing Database.AllowsCallouts, or restructure to do the callout before the DML.

03Composite API

The Composite API lets you execute multiple Salesforce API requests in a single HTTP call. Critical for the FAPO project where creating a Pledge Batch required simultaneously creating the batch record, its child items, and a related payment record.

Composite FeatureWhat It DoesMax Records
Composite (subrequests)Up to 25 requests in one call with response chaining using reference IDs25 subrequests
Composite BatchExecute independent requests in parallel — no chaining25 subrequests
SObject CollectionsCRUD on multiple records of the same or different types in one call200 records
SObject TreeCreate parent and child records in a single request using nested structure5 levels deep, 200 records
ApexComposite API — create parent and child in one call
public class CompositeAPIService {

    public static void createPledgeBatchWithItems(
            String batchName, List<Map<String,Object>> items) {

        // Build composite request body
        List<Map<String, Object>> subrequests = new List<Map<String, Object>>();

        // Subrequest 1 — create the parent Pledge Batch
        subrequests.add(new Map<String, Object>{
            'method'      => 'POST',
            'url'         => '/services/data/v63.0/sobjects/TFA_Pledge_Batch__c',
            'referenceId' => 'newBatch', // Reference ID for chaining
            'body'        => new Map<String, Object>{
                'Name'   => batchName,
                'Status__c' => 'Draft'
            }
        });

        // Subrequest 2 — create child item using @{newBatch.id} reference
        subrequests.add(new Map<String, Object>{
            'method'      => 'POST',
            'url'         => '/services/data/v63.0/sobjects/Pledge_Batch_Item__c',
            'referenceId' => 'newItem',
            'body'        => new Map<String, Object>{
                'Batch__c'   => '@{newBatch.id}', // Uses response from subrequest 1
                'Amount__c'  => 5000
            }
        });

        Map<String, Object> payload = new Map<String, Object>{
            'allOrNone'    => true, // Roll back all if any fail
            'compositeRequest' => subrequests
        };

        Http http = new Http();
        HttpRequest req = new HttpRequest();
        req.setEndpoint(URL.getOrgDomainUrl().toExternalForm()
                       + '/services/data/v63.0/composite');
        req.setMethod('POST');
        req.setHeader('Content-Type', 'application/json');
        req.setHeader('Authorization', 'Bearer ' + UserInfo.getSessionId());
        req.setBody(JSON.serialize(payload));
        HttpResponse res = http.send(req);
    }
}
allOrNone = true

When allOrNone is true, if any subrequest fails the entire composite operation rolls back — like a transaction. Set to false to allow partial success where successful subrequests are committed even if others fail.

04Named Credentials

Named Credentials store endpoint URLs and authentication details securely in Salesforce Setup. They eliminate hardcoded credentials and API keys from Apex code. All Claude API integrations in the AI Developer Toolkit use this pattern.

Apex Codereq.setEndpoint('callout:MIP_API/accounts') — no URL, no credentials in code
↓
Named CredentialStores: URL, Auth Protocol (OAuth/Basic/JWT), certificates
↓
External SystemReceives: authenticated request with correct headers — Apex never sees the credentials

From Summer 22 onwards Salesforce uses a two-object model: External Credential (stores the auth config) and Named Credential (the endpoint that references the External Credential).

ApexUsing Named Credential — Claude API callout
public class ClaudeAPIService {

    public static String analyseCode(String apexCode) {
        Http http = new Http();
        HttpRequest req = new HttpRequest();

        // Named Credential handles the base URL and API key header
        req.setEndpoint('callout:Anthropic_API/v1/messages');
        req.setMethod('POST');
        req.setHeader('Content-Type', 'application/json');
        req.setHeader('anthropic-version', '2023-06-01');
        req.setTimeout(60000);

        Map<String, Object> body = new Map<String, Object>{
            'model'      => 'claude-sonnet-4-6',
            'max_tokens' => 2000,
            'messages'   => new List<Object>{
                new Map<String, Object>{
                    'role'    => 'user',
                    'content' => 'Review this Apex class for issues: ' + apexCode
                }
            }
        };
        req.setBody(JSON.serialize(body));

        HttpResponse res = http.send(req);
        Map<String, Object> respMap =
            (Map<String, Object>) JSON.deserializeUntyped(res.getBody());
        List<Object> content = (List<Object>) respMap.get('content');
        Map<String, Object> firstBlock =
            (Map<String, Object>) content[0];
        return (String) firstBlock.get('text');
    }
}

05Connected Apps

A Connected App is a framework that enables an external application to integrate with Salesforce using OAuth 2.0. It defines the OAuth client ID and secret, the allowed OAuth flows, and the permission scope.

SettingValue / OptionsNotes
App NameMIP Integration AppDisplay name
Contact Emaildeveloper emailRequired
OAuth Scopesapi, refresh_token, offline_accessapi = access to Salesforce data. Add only what you need.
Callback URLhttps://yourdomain.com/oauth/callbackWhere Salesforce redirects after auth. Use https://login.salesforce.com/services/oauth2/success for testing
Client Credentials FlowEnabled for server-to-serverNo user interaction — external system authenticates as itself
Consumer Key and Secret

After saving a Connected App, Salesforce generates a Consumer Key (client_id) and Consumer Secret (client_secret). These are used by the external system to obtain access tokens. Store them securely — never commit to source control. Use Named Credentials or environment secrets.

06OAuth 2.0 Flows

FlowHow It WorksUse When
Web Server Flow (Authorization Code)User logs in → Salesforce redirects to callback with code → exchange code for tokenWeb applications where a user authenticates — Experience Cloud, external portals
User-Agent FlowToken returned directly to client in URL fragment — no server involvedSingle-page apps, mobile apps — token exposed in browser, less secure
Username-Password FlowSend username + password + security token directly to get access tokenLegacy integrations and testing only — Salesforce is deprecating this flow
Client Credentials FlowSend client_id + client_secret to get token — no user involvedServer-to-server integrations, MIP, background jobs, microservices
JWT Bearer FlowSign a JWT with private key → exchange for access tokenAutomated integrations, CI/CD pipelines, Salesforce CLI auth
Refresh Token FlowUse refresh_token to get a new access_token without re-authenticatingLong-running integrations where the access token expires

//Client Credentials Flow — Code Pattern

ApexGet access token via Client Credentials
public class OAuthService {
    public static String getAccessToken() {
        Http http = new Http();
        HttpRequest req = new HttpRequest();
        req.setEndpoint('callout:MIP_Auth/oauth/token');
        req.setMethod('POST');
        req.setHeader('Content-Type', 'application/x-www-form-urlencoded');
        req.setBody(
            'grant_type=client_credentials'
            + '&client_id=YOUR_CLIENT_ID'   // from Connected App
            + '&client_secret=YOUR_SECRET'    // store in Custom Setting, not here
            + '&scope=api'
        );
        HttpResponse res = http.send(req);
        Map<String,Object> tokenResp =
            (Map<String,Object>) JSON.deserializeUntyped(res.getBody());
        return (String) tokenResp.get('access_token');
    }
}

07Bulk API

The Bulk API processes large volumes of records asynchronously — up to 100 million records per 24 hours. Used in the BGCA project for large-scale fundraising data operations. Also the technology behind Data Loader.

FeatureBulk API 1.0Bulk API 2.0
Data formatCSV or XMLCSV only
Job creationMultiple stepsSingle endpoint
Record limit per batch10,000No batch concept — single job
PK chunking✅ Supported✅ Supported for queries
Recommended forLegacy integrationsNew integrations

In practice, most Salesforce developers use Data Loader for bulk operations rather than writing raw Bulk API code. For programmatic bulk operations from external systems, Bulk API 2.0 is the modern approach.

09Real Example — FAPO MIP Integration

The Financial Aid Payment Office project required bidirectional integration with MIP — a financial accounting system storing Chart of Accounts, GL entries, invoices, and payments. Here is the architecture we used.

Salesforce FAPOLoan Applications, Pledge Batches, Payment Records in Salesforce
↓ REST POST (Composite API) — create batch + items in one call
MIP Financial SystemChart of Accounts, GL entries, Invoices, Payments
↓ REST GET — fetch GL account data before posting
Salesforce FAPODisplay GL balance and account name on Pledge Batch record for officer review
↓ @future callout — async payment confirmation back to MIP
MIP Financial SystemMarks invoice as paid, updates GL

//Key Decisions Made

DecisionWhy
Named Credential for MIP authAPI key must not be in code — Named Credential stores it securely in Setup
Composite API for batch creationCreating batch + items in separate calls risks partial failure — Composite with allOrNone=true ensures both succeed or both roll back
@future for payment confirmation to MIPPayment confirmation happens after DML on Salesforce records — cannot make callout after DML in same transaction. @future runs in separate transaction.
REST not SOAP for MIPMIP supports both — REST is faster, JSON is easier to parse than XML, and the Apex code is significantly simpler
Typed response classesJSON.deserialize to typed class is safer than deserializeUntyped — compile-time checking catches missing fields during development

10External Services

External Services is Salesforce's no-code integration option — import an OpenAPI/Swagger spec and Salesforce generates invocable actions that can be used in Flows, Agentforce, and Process Builder without writing Apex.

When to use External Services vs Apex callout

Use External Services when the external API has an OpenAPI spec, the integration logic is simple (pass data in, get data back), and you want admin-maintainable no-code integration.
Use Apex callout when you need complex transformation, error handling, retry logic, callout chaining, or the API has no Swagger spec.
